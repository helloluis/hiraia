# Worker F contract requests

1. **Safe first-pass manual mapping / re-upload.** Add optional `columns: {index:number; field:RosterField}[]` and `headerRowIndex: number | null` to `RosterImportRequest`. Unmapped columns are discarded immediately because they may hold guardians, addresses or IDs. The current remap request only names a draft; it cannot recover discarded cells. The implemented remap supports retained name columns. Unmapped-column remap returns a plain-language paste/re-import fallback. The pure `structureRows` adapter already accepts explicit columns; initial mapping must be confirmed by the teacher, and sensitive header classifications must override manual mapping.
2. **Row conservation at the 500-student limit.** `RosterImportDraft.rows.max(500)` includes excluded letterhead/header/footer rows. A 500-student list plus one header exceeds it. Raise draft/source row limits separately (suggest 1000 source rows, retain 500 resulting students), or add a separate excluded-row representation/count. Current implementation safely rejects over 500 non-empty source rows instead of dropping rows.
3. **First-import notices and lasting cloud mark.** The returned draft has `route` and `aiUsed`, but confirm returns only students/pending indices and `Student.importId` refers to a purged draft. Add a non-personal import receipt (`importId`, route, aiUsed, confirmedAt) to confirmation/client records. The UI must display the bilingual notices supplied in `@hiraia/tala-core/roster` (`rosterNotices`), require acknowledgment each cloud import, and retain the early-access mark. No names should be in that receipt.
4. **Ambiguous text encodings.** Add optional `encoding` and an encoding warning on the draft for teacher-confirmed legacy decoding. The pure decoder supports strict UTF-8, BOM UTF-16, and explicitly uncertain Windows-1252/Latin-1 fallback; unsupported/control-bearing encodings return the paste/UTF-8 fallback. Generic `corrupted_characters` flags currently carry the uncertainty. Arbitrary legacy encodings cannot be reliably inferred from bytes alone.
5. **Network-safe partial confirmation.** Confirm returns client-created students and consumes those rows; a lost response cannot safely be retried. Add a caller-provided confirmation operation ID and stable student IDs (or a client ACK route), with a short encrypted response receipt. Current draft-only contract has no idempotency/ACK semantics; clients must not automatically replay confirmations.

Production gate remains external: assessed/evaluated local route, PIA, transport/device/server encryption, retention/deletion and backup policy. The roster module never writes source files or drafts to persistent storage; it cannot establish device encryption or deployment compliance.
