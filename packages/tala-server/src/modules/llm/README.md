- https://help.aliyun.com/en/model-studio/qwen-structured-output — json_object requires JSON keyword; json_schema strict is supported only on selected models. Adapter requests JSON object in non-thinking mode and validates with caller Zod/check.

Pricing is not guessed: the gateway reads ProviderConfig.pricing only. The config loader reads TALA_LLM_PRIMARY_INPUT_USD_PER_MILLION / TALA_LLM_PRIMARY_OUTPUT_USD_PER_MILLION and TALA_LLM_FALLBACK_INPUT_USD_PER_MILLION / TALA_LLM_FALLBACK_OUTPUT_USD_PER_MILLION. Set both rates to account/model rates. Unknown rates fail closed with budget_exceeded. Local defaults to zero external cost. Token metering includes failed validation calls. One gateway serializes calls. Each provider attempt reserves its worst-case cost transactionally in SQLite before dispatch, then replaces it with metered cost. Timeout/network-uncertain calls retain the conservative reservation to avoid undercounting possible charges. Cross-process gateways share those reservations. Cache is bounded, memory-only, per user, and every hit is revalidated against the caller schema/check. Persistent ledger stores no prompt, response, or plan text. Generation jobs necessarily persist inputs/results in their separate owner-scoped table.

V2 generation uses compact per-template JSON, not the storage schema. The server resolves exact objective refs, generates IDs and RichText, and supplies fixed timing/focus slots. Multi-grade slots cover opening, one focus slot per grade, and closing; other grades must receive unaided work. The model writes the differentiated activities. This is deterministic structural safety, not a pedagogical or factual alignment check. Translation emits only allowlisted text-leaf replacements, preserving IDs, timing and formatting. Version 1 lesson prompts remain unchanged; explicit v1 selection uses the old storage schema for rollback.

Every attempt exposes metadata-only diagnostics through onAttempt: status/error class/provider code, finish reason, usage, latency and validation stage with redacted schema paths or named rules. HTTP envelope JSON failures are separate from completion JSON failures. finish_reason=length triggers the normal one retry with a tighter instruction, before JSON parsing. Output allowances are 4096 tokens for a section, 8192 for a single/two-group plan, and 12288 for weekly/three/four-group plans; these limits enter cost reservations.

The account-deletion hook cancels queued/in-flight requests, clears that user's cache, deletes usage/quota rows, and preserves only month-level anonymous spending totals. It prevents both data resurrection and resetting the global budget by deleting an account.

Account merge transfers usage ownership and sums daily quota counters on (day, bucket) collisions; total global spend stays unchanged. Cached identical requests are rekeyed to the destination owner; if both accounts have the same entry, the later-expiring one wins. Source-account in-flight/queued requests are cancelled so they cannot create new rows for the retired identity. Generation's hook preserves their persistent inputs and requeues running jobs under the destination owner. Repeating either hook, or merging an account into itself, is a no-op after the first transfer.

Objective display uses the core formatCompetencyObjective helper: official code (when nonempty), then stored text; never the internal curriculum ID. Compact requests use opaque objective-N refs rather than internal IDs. For offline prefilled drafts, pass stored code/text records as resolvedCompetencies, or already formatted strings as resolvedObjectives; without resolved text the helper leaves objectives empty instead of displaying raw IDs. Existing ID-prefixed draft strings are stripped for compatibility. Plan/input competency-ID mappings remain unchanged.
