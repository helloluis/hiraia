Direct API verification (2026-11-13)

- DeepSeek official Chat Completions docs: https://api-docs.deepseek.com/api/create-chat-completion/ — POST /chat/completions, bearer auth, messages, model, response_format json_object. JSON Schema is also documented in the separate Responses API; this adapter deliberately uses JSON-object mode and validates locally. Docs currently list deepseek-flash/deepseek-v4-pro; the requested v4.1 name must be configured from the actual account's model catalogue, never assumed from an Alibaba model name.
- Alibaba official API docs: https://help.aliyun.com/en/model-studio/qwen-api-via-openai-chat-completions — direct compatible-mode/v1/chat/completions, regional workspace domains; existing dashscope-intl.aliyuncs.com remains functional. Base URL is configured, not inferred from credential.
- https://help.aliyun.com/en/model-studio/qwen-structured-output — json_object requires JSON keyword; json_schema strict is supported only on selected models. Adapter requests JSON object in non-thinking mode and validates with caller Zod/check.

Pricing is not guessed: set TALA_LLM_DEEPSEEK_INPUT_USD_PER_MILLION / OUTPUT_USD_PER_MILLION and TALA_LLM_QWEN_INPUT_USD_PER_MILLION / OUTPUT_USD_PER_MILLION to account/model rates. Unknown rates fail closed with budget_exceeded. Local defaults to zero external cost. Token metering includes failed validation calls. One gateway serializes calls to protect its budget ceiling; use one server process per database until durable cross-process reservations are added. Cache is bounded, memory-only, per user, and every hit is revalidated against the caller schema/check. Persistent ledger stores no prompt, response, or plan text. Generation jobs necessarily persist inputs/results in their separate owner-scoped table.
