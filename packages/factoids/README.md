# @hiraia/factoids — daily "Alam mo ba na…?" message

The bones of a **scheduled, unprompted** message the tutor sends the student
every **morning (07:00)** and **evening (20:00)**: a random science factoid plus
its matching picture.

```
Alam mo ba na ang mga bubuyog ay may iisang reyna na siyang ina ng halos lahat
ng pukyutan sa pugad? Kaya niyang mangitlog ng hanggang 2,000 itlog sa isang
araw — mas mabigat pa sa kabuuang timbang niya! …                 🖼 bee-bubuyog
```

Format is fixed: **`Alam mo ba na <hook>? <body>`** (`Did you know that …?` /
`Nahibaw-an ba nimo nga …?` in the other languages).

## Why it's built this way

The hard part is that the factoid must be **correct**. The on-device model is
tiny (Qwen3-1.7B) and hallucinates, so we do **not** let it invent facts live.
Instead:

1. **Curated + verified bank** — factoids are authored and fact-checked *offline*
   and stored with `verified: true`. The runtime only ever serves verified ones,
   so a wrong fact can never reach a kid unsupervised.
2. **Image-anchored** — each factoid is tied to a real subject in the image
   library (`packages/images/index.json`), so the matching picture is a
   guaranteed direct lookup, not a fuzzy search.

```
OFFLINE (build/regenerate)                 RUNTIME (07:00 / 20:00)
  pick image subject ─► draft factoid        sample a verified factoid
        │                    │                      │ (no recent repeat)
        ▼                    ▼                      ▼
   strong model        verify (fact gate)     compose "Alam mo ba na…?"
        │                    │                      │
        └──► bank/staging.json ──promote──► bank/factoids.json ──► + anchor image
                                (verified:true)
```

## Quick start

```bash
cd packages/images && node build-index.mjs      # one-time: build the image index
cd ../factoids

npm run demo                       # preview a morning + evening message
node src/cli.mjs --count 5         # preview five (rotates, no repeats)
node src/cli.mjs --slot morning --lang english --grade 5
node src/cli.mjs --slot evening --send   # REAL send: records history, prints message JSON
npm test                           # 17 unit tests, zero install (node:test)
```

## Regenerating the bank (the part that scales with your fine-tunes)

Everything is **idempotent and incremental** — re-running skips finished work;
`--force` redoes it. The model is chosen entirely by env, so point it at whatever
gives the best output today. As your **Tagalog/Cebuano fine-tunes improve, you
re-render the language fields without re-checking any facts** (see "fact vs
phrasing" below).

```bash
# Where the pipeline gets its model (any OpenAI-compatible /v1/chat/completions):
export HIRAIA_LLM_BASE_URL=http://127.0.0.1:8080   # the @hiraia/server sidecar
export HIRAIA_LLM_MODEL=local
# export HIRAIA_LLM_API_KEY=...                     # for a hosted endpoint
# export HIRAIA_LLM_ADAPTER=cebuano                 # adapter hint (sidecar logs it)
```

**1. Refresh Cebuano (or Tagalog) as a fine-tune lands** — the common case:

```bash
# start the sidecar with your best Cebuano adapter, then:
node scripts/generate-factoids.mjs --mode translate --lang ceb           # fill missing only
node scripts/generate-factoids.mjs --mode translate --lang ceb --force   # re-render ALL ceb
node scripts/generate-factoids.mjs --mode translate --lang tl   --force  # re-render Tagalog
```

This only touches `hook`/`body` phrasing; the verified fact (`source`) is left
alone, and provenance is stamped (`provenance.langMeta.ceb = { by, at }`) so you
can see what each adapter produced and what's stale.

**2. Grow the bank with new factoids:**

```bash
node scripts/generate-factoids.mjs --mode draft --limit 30 --subject biology
#   → drafts (verified:false) land in bank/staging.json
node scripts/verify-bank.mjs
#   → fact-checks each; PASS → bank/factoids.json (verified:true), FAIL stays staged with a note
```

**3. Audit facts already live (e.g. with a stronger model):**

```bash
node scripts/verify-bank.mjs --recheck     # flags anything it's no longer confident about
```

No server handy? Add `--mock` to any of the above to exercise the plumbing with
canned output (clearly marked placeholders — never real facts).

### Fact vs phrasing

Each factoid separates **what is true** from **how it's said**:

| field | meaning | regenerated by |
|---|---|---|
| `source` | the single factual claim (English, language-neutral) | rarely; this is what `verify` checks |
| `verified` / `verifiedBy` | the truth gate | `verify-bank.mjs` |
| `hook` / `body` `{tl,en,ceb}` | the per-language renderings | `translate` mode — re-run freely as fine-tunes improve |
| `provenance.langMeta` | which model rendered each language, when | stamped automatically |

Because translations are renderings of an already-verified fact, improving them
is cheap and safe — no fact ever needs re-checking just because the Cebuano got
better.

## Scheduling & integration

This package owns the *content* and the *timing decision*, not a delivery
channel. Wire it to whatever the app uses (push, in-app inbox, server cron).

**Timezone matters:** "07:00" and "20:00" only mean something in a timezone, and
it must be the **student's** — a morning message should land in *their* morning.
The default is **`Asia/Manila` (GMT+8)** since Hiraia is Filipino-centric; pass a
per-student IANA zone to override. Slot evaluation is DST-correct (via `Intl`),
not the server's local clock.

```bash
# crontab — run the slot check every hour; CRON_TZ pins the zone the times mean.
# (Per-student delivery should instead loop students and call with each one's tz.)
CRON_TZ=Asia/Manila
0 7  * * *  cd /path/to/hiraia && node packages/factoids/src/cli.mjs --slot morning --send
0 20 * * *  cd /path/to/hiraia && node packages/factoids/src/cli.mjs --slot evening --send
# or let the slot be derived from the current time in a zone:
0 * * * *   cd /path/to/hiraia && node packages/factoids/src/cli.mjs --send --tz Asia/Manila
```

or in code (the per-student path):

```js
import { runScheduledMessage } from '@hiraia/factoids';

// Called hourly per student; sends only when it's 07:00/20:00 in their zone.
await runScheduledMessage({
  timeZone: student.timeZone || 'Asia/Manila', // GMT+8 default
  language: student.language,                  // 'tagalog' | 'english' | 'cebuano'
  grade: student.grade,
  send: (msg) => pushToStudent(msg),           // { text, image, factoidId, slot, language, timeZone }
});
// slot is derived from now in the student's zone; off-slot → resolves null, no send.
```

`--send` / `runScheduledMessage` record the served id to a rolling history
(`.state/history.json`) so the bank cycles before anything repeats.

## Files

```
packages/factoids/
  bank/factoids.json        the verified bank (the only thing runtime serves)
  bank/staging.json         drafts awaiting verification (gitignored, regenerable)
  src/
    types.mjs               data contracts (JSDoc; shared with TS consumers)
    bank.mjs                load + no-repeat sampling + history
    retrieve.mjs            resolve anchor image by id (+ TF-IDF fallback for factoid-first)
    compose.mjs             the "Alam mo ba na…?" assembly + language fallback
    service.mjs             nextFactoidMessage() — the one call a channel makes
    schedule.mjs            slot timing + runScheduledMessage(send)
    cli.mjs                 preview tool + cron entrypoint
  scripts/
    llm.mjs                 pluggable OpenAI-compatible client (+ --mock)
    generate-factoids.mjs   draft new + translate existing
    verify-bank.mjs         the correctness gate (promote / recheck)
  test/                     node:test unit tests (npm test, zero install)
```
